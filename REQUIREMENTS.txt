Purpose of this assessment
Coursework Overview: GeoQuest - Location-Based Treasure Hunt App
This is a mobile application development project in which you will develop a significant mobile application in pairs using an agile approach. You will allocated the technology to develop within either React Native (JS), Android (Kotlin), or iOS (Swift).

You will showcase your design and programming skills through the development of a functional location-based application. While you will work in pairs, marking is individual and based on your personal contribution and performance. 

You are required to design and develop GeoQuest, a location-based treasure hunt app inspired by real-world geocaching.

GeoQuest enables users to discover and log virtual caches tied to real-world GPS locations. Users must physically travel to locations and use mobile sensors and application features to unlock and record finds.

This assignment simulates a realistic mobile development scenario involving:
•    Mobile sensors
•    Platform frameworks
•    APIs
•    Persistent data
•    UX and UI design considerations
•    Platform-specific conventions

Learning Outcomes
The following module learning outcomes and professional body learning outcomes are tested in this assessment:

Design and develop portfolio applications for two mobile platform environments.
Explain the differences between native and cross-platform mobile application development, and the benefits and limitations of cross-platform involves.
Make an informed choice between native and cross-platform based on application and project requirements.
Design applications that conform to UX best principles and UI conventions of both major platforms, and understand the differences between them.
Coursework specification
The following presents the main project objectives:
1. Scenario
A cache is a virtual treasure placed at a real-world GPS location. When a player is within a defined proximity, the cache can be unlocked and logged.

Each cache may include:
•    Title and description
•    GPS coordinates
•    Clue or riddle
•    Points value
•    Optional photo evidence

Your app must support discovery, navigation, and logging of caches.

2. Gameplay Modes
Your application must support at least one of the following. Supporting both may attract higher marks.

Option A: Global Mode
A shared world where users can:
•    View public caches on a map
•    Navigate to caches
•    Log discoveries
•    Earn points
•    View leaderboards

Option B: Private Event Mode
Users can create private events for:
•    Families
•    Schools
•    Companies
•    University activities

Event owners can:
•    Create caches
•    Set time windows
•    Share invite codes
•    Track participant progress

Participants can:
•    Join via code
•    View event caches only
•    Compete on event leaderboards

3. Mandatory Technical Requirements
Sensor Use

Use at least two of the following sensors (but not limited to):
•    GPS or location services (required)
•    Accelerometer or step counter
•    Compass or gyroscope
•    Camera

Sensor use must be meaningful and directly related to app functionality.

Data Persistence

Include at least one:
•    Local database or storage
•    Cloud DB backend e.g. Realms, Firebase, or other (note: that any costs occurred are your own)
•    GeoQuest REST API integration (KU provided)

Map Integration

A map must be used to:
•    Display caches
•    Show user location
•    Support some form of navigation

User Interface
Your app must demonstrate:
•    Multiple screens
•    Clear navigation
•    Consistent design
•    User feedback and status indicators
•    Consideration of platform UI conventions

4. User Interface
The app must feature a clean, modern, and intuitive mobile interface
UI design should prioritise short, frequent interactions
Platform-appropriate UI frameworks must be used:
SwiftUI for iOS
Jetpack Compose for Android
Navigation should be clear and consistent across the app
Components should be used to ensure consistency and reusability.
5. Agile Working Requirement
As this is a paired project, you should demonstrate through your GitHub repository:
•    Task planning or backlog
•    Iterative development
•    Evidence of collaboration
•    Version control usage

A short summary of your agile process must be included in the individual report.
